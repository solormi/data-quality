# data-quality 测试用例集

> 3 份故意带不同类型违规的 SQL + 对应数据特征 md,用于在 Web UI / CLI 上验证工具识别能力。

## 用例速查

| 用例 | SQL 文件 | 文档文件 | 覆盖的违规类型 |
|------|---------|---------|--------------|
| A:会员活跃度日报 | `case-a-member-active.sql` | `case-a-member-active.md` | 字段误用(字段名错)、缺失多个已知过滤 |
| B:订单金额汇总 | `case-b-order-summary.sql` | `case-b-order-summary.md` | 单位混淆、状态枚举漏过滤、缺 LIMIT |
| C:渠道拉新统计 | `case-c-channel-conversion.sql` | `case-c-channel-conversion.md` | 全表扫描、JOIN 无分区键、整数除法 |

## 推荐测试顺序

按识别难度从低到高,先 A 后 C:

1. **用例 A** —— 最容易,踩坑点都在过滤条件上
2. **用例 B** —— 中等,加入单位混淆这种语义判断
3. **用例 C** —— 最难,涉及性能 / JOIN 策略,LLM 命中率较低

## Web UI 测试方法

1. 浏览器打开 `http://localhost:3000`
2. 打开对应 md 文件,复制"字段 / 表信息"和"报表口径要求"两段 → 粘贴到右文档框
3. 打开对应 sql 文件,复制全部 → 粘贴到左 SQL 框
4. 点 `审查`
5. 对照下方"这份 SQL 应该被识别出的违规"列表,看实际报告覆盖了几条

## CLI 测试方法

```bash
./docs/start.sh --cli docs/test-cases/case-a-member-active.sql docs/test-cases/
```

> 注意:CLI 模式 `--docs` 接收的是**目录**,工具会加载该目录下所有 md 文件。如果该目录有多个 md,LLM 会自动综合所有信息。

## 评分建议

每个用例跑完后,人工对照 md 末尾的"应该被识别出的违规"列表,数实际报告命中了几条。

- **5/5 命中**:工具能力优秀,可以直接接入 CI
- **3-4 命中**:能力可用,可考虑优化 `prompts/review.md` 后再试
- **< 3 命中**:可能 prompt 模板需要调优,或种子文档描述不够清晰

## 自定义测试用例

想覆盖自己的业务场景,新建一份 `<case-name>.md` + `<case-name>.sql` 即可。md 里要包含:

- 表名 + 字段表(尤其是**已知问题**列)
- 报表口径(过滤条件、输出字段、强制约束)
- "应该被识别出的违规"列表(给自己对照用)

LLM 的识别能力高度依赖文档写得**清晰且具体**(避免模糊表述)。

## 与 samples/ 的关系

`samples/` 目录是项目自带的、相对严肃的示范(场景完整、文档格式标准)。

`docs/test-cases/` 是这份配套的测试集,**故意踩坑 + 标注预期**,用于功能验证。
两者定位不同,可并存使用。
